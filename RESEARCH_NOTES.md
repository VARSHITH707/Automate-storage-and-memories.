# Research notes

Checked 2026-10-23. Official sources first. "Implication" says what it changes in this app.

| Topic | Source | Fact | Implication / decision |
|---|---|---|---|
| Package versions | `pip index versions` (PyPI), 2026-10-23 | telethon 1.45.0, typer 0.27.3, faster-whisper 1.2.1, google-api-python-client 2.201.0, google-auth-oauthlib 1.5.0, google-auth 2.62.0, keyring 25.7.0, pillow 13.0.0, pytest 9.1.1, ruff 0.17.2 | Pin compatible ranges on these. Telethon stays on the 1.x API (2.x is a different API). |
| Telethon events | https://docs.telethon.dev/en/stable/quick-references/events-reference.html | `NewMessage` fires for new text or media messages. `Album` fires for a whole album; album messages share `grouped_id`. | Live intake uses `NewMessage` on the Inbox. Albums are grouped in our DB by `grouped_id`, so catch-up and live events share one path (DECISIONS D-07). |
| Telethon sessions | https://docs.telethon.dev/en/stable/concepts/sessions.html | A session is an SQLite file holding the auth key and cached entities. "Anyone with this string can use it to login into your account" (string sessions; same for `.session` files). | Session files live in the per-user app-data folder, never in the repo, with owner-only permissions where the OS allows. |
| Telethon client | https://docs.telethon.dev/en/stable/modules/client.html | `flood_sleep_threshold` (default 60 s): flood waits at or below it are slept automatically; longer ones raise. `start(bot_token=...)` logs in a bot. `catch_up` constructor flag exists. | Longer flood waits become a bounded retry with `next_attempt_at`. Bot uses its own session file. Method signatures checked against the installed 1.45.0 package. |
| Telegram discussion | https://core.telegram.org/api/discussion | Broadcast-channel posts are commented on only through a linked discussion group; forwarded copies there have `from_id` = the channel. | Approvals use the bot's private chat by default (DECISIONS D-03). Channel posts do not reliably name the human poster, so setup requires the Inbox to have no other admins (D-05). |
| Telegram API terms | https://core.telegram.org/api/terms | Apps must protect privacy, cannot act without the user's consent, must use their own api_id, and "cannot use data obtained from Telegram to train, fine-tune, or build AI or machine learning models". | Owners use their own api_id. The app runs inference only and never trains or fine-tunes on media. Stated in PRIVACY.md. |
| Ollama vision | https://github.com/ollama/ollama/blob/main/docs/capabilities/vision.mdx | REST `/api/chat` takes `images: [<base64>]` inside a message; `stream:false` returns one JSON. | Vision adapter sends base64 JPEG thumbnails through stdlib `urllib` to `127.0.0.1:11434`. No extra dependency. |
| Ollama models | https://ollama.com/library/gemma3 , https://ollama.com/library/qwen3-vl , https://ollama.com/library/gemma4 | gemma3:4b 3.4 GB, image input, Gemma Terms of Use. qwen3-vl:2b 1.9 GB, image input (license not shown on page). gemma4 smallest tag 4.6 GB+. | Default `gemma3:4b` for vision and text (fits 16 GB). Low-RAM option `qwen3-vl:2b`; its license must be checked with `ollama show qwen3-vl:2b --license` before recommending. No weights bundled. |
| faster-whisper | https://github.com/SYSTRAN/faster-whisper | `WhisperModel(size, device="cpu", compute_type="int8")`; `transcribe()` returns a lazy segment generator and `info.language`. Models download from Hugging Face (Systran). FFmpeg not needed (PyAV bundles it). Library license MIT. | Optional extra `[whisper]`; lazy import so the core and CI run without it. Model `small`, int8, CPU. Weight licenses are on the Hugging Face model cards. |
| YouTube insert | https://developers.google.com/youtube/v3/docs/videos/insert | Scopes accepted include `youtube.upload`. Cost: 1 unit from the separate Video Uploads bucket (100 calls/day). "Videos uploaded from unverified API projects are not restricted to private viewing mode." Max 256 GB; `video/*` or `application/octet-stream`. | Scope `youtube.upload` only. The app must set `privacyStatus="private"` itself, because Google no longer forces it. Up to 100 uploads/day per Google project. |
| YouTube resumable | https://developers.google.com/youtube/v3/guides/using_resumable_upload_protocol | Session URI from `Location`. A status check is an empty PUT with `Content-Range: bytes */TOTAL`. 308 = incomplete (with a `Range` header), 201/200 = done (a completed upload returns its final response again), 404 = expired session. 5xx = retry with backoff. | Persist the session URI before sending bytes. On restart, query the session. If the result is unknown and cannot be queried, set `upload_unknown` and require reconciliation (D-11). |
| YouTube quota | https://developers.google.com/youtube/v3/determine_quota_cost | Default 10,000 units/day for most methods; `videos.insert` and `search.list` have their own buckets. | Quota errors become a bounded retry with a clear message, never a tight loop. |
| Google OAuth (desktop) | https://developers.google.com/identity/protocols/oauth2/native-app | Desktop apps are public clients; the secret is not confidential. Loopback redirect recommended; always use PKCE; store refresh tokens securely. | Use `google-auth-oauthlib` `InstalledAppFlow.run_local_server` (loopback). Store the refresh token in the OS keyring. The 7-day Testing-mode expiry was not on this page; it is documented in TROUBLESHOOTING as "from Google's OAuth docs; verify". |
| keyring | https://github.com/jaraco/keyring | Windows Credential Locker, macOS Keychain, Linux Secret Service/KWallet. `keyring.get_keyring()` returns the active backend. `keyrings.alt` holds possibly-insecure backends; a Null backend stores nothing. | `doctor` rejects fail/null/plaintext backends and never falls back to plaintext. |
| SQLite | https://docs.python.org/3/library/sqlite3.html | Python's sqlite3 supports explicit transactions (`isolation_level=None` + `BEGIN IMMEDIATE`). | One writer process; WAL mode; foreign keys on; compare-and-set state transitions. |

## Not verified

- Telegram's exact rule for how long bot updates are kept while the app is offline was not found in official docs. The owner can re-send a reply if one is missed (TROUBLESHOOTING).
- The YouTube 7-day refresh-token expiry for apps in Testing was not confirmed in the pages read.
